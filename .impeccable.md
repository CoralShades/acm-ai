# Design Context

> Established: 2026-03-22 | Product: VAEA | ACM AI | Vendor: CoralShades
> This file guides all design decisions for Claude Code and AI assistants working on this project.

---

## Users

**Primary persona**: Victorian government compliance officers (intermediate tech level — comfortable with spreadsheets, not developer tools). They sit at desks with large monitors but also use tablets and phones in the field.

**Three named personas:**
- **Sarah** (School Facility Manager) — quick ACM location lookup before maintenance
- **Mike** (Compliance Officer) — generate reports, track risk status across schools
- **Lisa** (Asbestos Assessor) — verify register accuracy, update findings

**Context**: Users process Asbestos Register Assessment (ARA) PDF documents into structured, Salesforce-ready data. They work with data-heavy grids (24+ columns), building-by-building workflows, and AI-assisted extraction. The tool must feel like government infrastructure — not a startup product.

**Job to be done**: "Get accurate ACM data into Salesforce quickly, with confidence that nothing was missed or misclassified."

---

## Brand Personality

**Three words**: Professional, Transparent, Calm

**Emotional tone**: Confidence & Trust — "I can rely on this data." The interface should feel like a trusted institutional tool. When a compliance officer sits down, they should feel the same institutional authority as using an ATO portal or Xero dashboard, but with modern polish.

**Voice**: Direct, factual, no jargon. Status messages state what happened, not what might have happened. Error messages explain what to do next. Labels are precise — never clever.

## Aesthetic Direction

### References
- **Salesforce**: Enterprise CRM patterns (the data goes there), familiar grid/form conventions, field-level validation
- **Xero**: Clean Australian government-friendly accounting UI, professional restraint, data density done right

### Anti-References (ALL of these)
- **Generic SaaS / startup**: No gradient hero sections, no "Get Started Free" energy, no playful illustrations
- **Legacy government portals**: No grey-on-grey brutalism, no Times New Roman, no 2005 .gov.au aesthetic
- **Over-designed / trendy**: No glassmorphism, no gratuitous animations, no dark-mode-only aesthetic
- **Dense enterprise ERP**: No SAP/Oracle overwhelming density — even data-heavy views need visual rhythm

### App vs Marketing Site
The app and marketing site are **intentionally different identities**:
- **App**: Inter + JetBrains Mono, utilitarian, data-dense, government-grade
- **Marketing**: DM Serif Display + DM Sans, editorial, aspirational, "Institutional Precision"
- **Shared**: VAEA color palette, spacing rhythm, teal brand identity

### Theme
- **Light mode**: Clean whites and light greys with VAEA teal accents
- **Dark mode**: Distinctive teal-tinted backgrounds (NOT neutral grey) — branded and recognizable. This is a deliberate choice — "this is my VAEA app"
- **Both modes** use oklch color space for perceptually uniform color manipulation

## Design Principles

### 1. Confidence Through Precision
Every data point, status indicator, and validation message must inspire trust. Use dual encoding (icon + color) for risk levels. Never display ambiguous states. If the system doesn't know something, say "Unknown" — never guess.

### 2. Data Density Without Clutter
ACM registers contain hundreds of rows. Every pixel of information density matters. When card layouts and grid layouts conflict, **data density wins**. But density requires visual rhythm — use consistent spacing, clear column alignment, and whitespace between logical groups to prevent wall-of-text fatigue.

### 3. Progressive Disclosure
Show what matters now, reveal complexity on demand. Compliance officers see simple defaults; power users can reveal advanced controls. Jobs dashboard is generous; ACM records grid is dense. Two modes within one system.

### 4. Source Always Available
One click from any record to the source PDF page. Provenance is not optional — it's the core trust mechanism. Every extracted data point should be traceable to its origin.

### 5. Never Block, Always Guide
Validation warns during editing, blocks only on export. The interface should guide users toward correct data, not gatekeep them from working. Error states explain what to do next.

Coral is no longer reserved for focus rings only. Use it for:
- Primary CTAs and action buttons (alongside teal for secondary actions)
- Important badges and notification dots
- High-priority status indicators
- Focus rings (original role)
- Critical alerts and destructive action confirmation

### Risk Status Colors (Dual Encoded)
Every risk level MUST have a distinct icon/shape alongside color — never rely on color alone:
| Level | Color | Icon | Purpose |
|-------|-------|------|---------|
| Low | Green | Checkmark (circle) | Confirmed safe or managed |
| Medium | Amber | Triangle (warning) | Requires monitoring |
| High | Red | X-circle | Immediate attention needed |
| Presumed | Purple | Question-mark (circle) | Unconfirmed, assumed present |

## Typography

### App Fonts
- **Body**: Inter (migrate to `next/font/google` for self-hosting, subsetting, zero-layout-shift)
- **Code/Data**: JetBrains Mono with `font-variant-numeric: tabular-nums` for aligned numbers
- **Data display**: JetBrains Mono via `font-data` utility class

### Font Loading (Action Required)
Current: Google Fonts `<link>` tags at runtime (FOUT risk, no subsetting, Google tracking)
Target: `next/font/google` self-hosted (zero-layout-shift, automatic subsetting, no external requests, government privacy compliance)

### Scale
8 sizes from `xs` (0.75rem/12px) to `4xl` (2.25rem/36px), each with explicit line-height pairing. Headings use negative letter-spacing (-0.02em for h1, -0.01em for h2).

---

## Spacing & Layout

### Spacing Scale
4px base grid: `space-0` (0) through `space-24` (6rem/96px). Use the design token variables, not raw pixel values.

### Border Radius
12px base (`--radius: 0.75rem`) — government standard. Derived: `sm` (calc - 4px), `md` (calc - 2px), `lg` (base), `xl` (base + 4px).

### Shadows
Branded teal-tinted shadows in light mode (`rgba(42, 89, 81, ...)`). Pure black in dark mode. Five levels: `xs` through `xl`.

## Responsive Strategy

### True Responsive (All Devices)
Every feature must work on desktop, tablet, and phone. This is non-negotiable.

### Data Grid Mobile Strategy
Below `md` breakpoint, **replace AG Grid with stacked cards** showing key fields (building code, item name, risk level, location). Tap to expand full record. Pattern: Salesforce mobile app.

Above `md`: full AG Grid with horizontal scroll and pinned key columns.

### Breakpoint Conventions
| Breakpoint | Target | Grid behavior |
|-----------|--------|---------------|
| < 640px (mobile) | Phone | Card stacks, single column, Sheet overlays for chat |
| 640-768px (sm) | Large phone / small tablet | 2-column card grids |
| 768-1024px (md) | Tablet | AG Grid appears, 2-column layouts |
| 1024-1280px (lg) | Desktop | Sidebar + content, full grid |
| 1280px+ (xl) | Large desktop | 4-column card grids, expanded data density |

## Motion & Animation

### Direction: Invest in Motion Design
Add `framer-motion` for:
- **Page transitions**: Smooth route changes with shared layout animations
- **List reordering**: AnimatePresence for adding/removing items in lists and grids
- **Dialog enter/exit**: Spring-based open/close for modals and sheets
- **Micro-interactions**: Subtle feedback on button clicks, toggle switches, status changes
- **Progress indicators**: Smooth number counting, stage transitions during extraction

### Current CSS Animations (Keep)
- `animate-shimmer`: Skeleton loading (2s linear infinite)
- `animate-spin`: Loading spinners
- `animate-pulse`: Extraction status dots, streaming indicators
- `animate-bounce`: Staggered dots in processing states
- `transition-colors`: 150ms for interactive elements
- `transition-all duration-200`: Sidebar and panel collapse/expand

### Reduced Motion
Not a priority right now. Current CSS-only animations are subtle enough. Address in a formal accessibility audit later.

## Accessibility

### Target: WCAG 2.2 AAA (Aspirational)
Go beyond AA where practical. Enhanced focus indicators, generous target sizes, cognitive load reduction.

### Current Strengths (Preserve)
- ARIA attributes on 75+ elements
- `aria-live="polite"` on streaming regions
- `role="progressbar"` with min/max/now values
- Skip-to-content link in root layout
- Keyboard shortcuts (Ctrl+K, E, Delete, Enter, Space)
- `focus-visible` ring classes on all interactive elements

### Known Gaps (Fix)
- Login form password input needs explicit `<label>` element
- Search inputs need `aria-label` attributes
- Mobile chat FAB needs descriptive accessible name
- Risk indicators need dual encoding (icon + color) — see Color System above

### Aboriginal Acknowledgment
Required for all Victorian government applications. Present in footer via `branding.ts` config.

## Component Architecture

### Pattern: shadcn/ui (Radix + CVA + Tailwind + cn)
All 38 UI primitives follow this pattern. Hand-maintained in `frontend/src/components/ui/`. Do NOT use the shadcn CLI — maintain components manually to preserve customizations.

### AG Grid Theme (Action Required)
Current: Inline `<style jsx global>` blocks duplicated between BuildingGrid and ACMGrid.
Target: **Consolidate to one canonical `.ag-theme-custom` definition in `globals.css`**. Remove all inline style blocks. Single source of truth.
