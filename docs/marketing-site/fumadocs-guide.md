# Fumadocs Documentation Guide

The marketing site uses [Fumadocs](https://fumadocs.vercel.app/) for its documentation platform at `/docs`.

## Architecture

```
marketing-site/
  source.config.ts           ← Fumadocs MDX collection definitions
  .source/                   ← Auto-generated (gitignored) — DO NOT EDIT
    server.ts                ← Generated docs + meta collections
    browser.ts               ← Client-side exports
  src/
    lib/source.ts            ← Loader config (converts collections to Fumadocs source)
    app/docs/
      layout.tsx             ← DocsLayout with VAEA-themed sidebar + RootProvider
      [[...slug]]/page.tsx   ← Dynamic page renderer
    content/docs/            ← MDX content files live here
      index.mdx
      meta.json              ← Top-level sidebar order
      prd/
        meta.json            ← Section sidebar order
        index.mdx
        functional-requirements.mdx
        data-model.mdx
        api-endpoints.mdx
      architecture/
        meta.json
        index.mdx
        pipeline.mdx
        tech-stack.mdx
      epics/
        meta.json
        index.mdx
      guides/
        meta.json
        quick-start.mdx
        bar-compliance.mdx
```

## Adding a New Documentation Page

1. Create the MDX file in the appropriate directory:
   ```
   src/content/docs/my-section/my-page.mdx
   ```

2. Add frontmatter:
   ```mdx
   ---
   title: My Page Title
   description: Brief description for SEO and sidebar
   ---

   # My Page Title

   Content here. Supports GitHub-flavored markdown, code blocks with syntax
   highlighting, callouts, and more.

   ## Subheading

   Regular markdown content...
   ```

3. Update the section's `meta.json` to include the new page in sidebar order:
   ```json
   {
     "title": "My Section",
     "pages": ["index", "my-page", "another-page"]
   }
   ```

4. Run `npm run build` — Fumadocs regenerates `.source/` automatically.

## Adding a New Documentation Section

1. Create the directory:
   ```
   src/content/docs/new-section/
   ```

2. Create `meta.json` for sidebar ordering:
   ```json
   {
     "title": "New Section",
     "pages": ["index", "first-page"]
   }
   ```

3. Create `index.mdx` as the section landing page:
   ```mdx
   ---
   title: New Section
   description: Overview of this documentation section
   ---

   # New Section

   Overview content...
   ```

4. Update the root `src/content/docs/meta.json` to include the new section:
   ```json
   {
     "title": "ACM-AI Documentation",
     "pages": [
       "index",
       "---PRD---",
       "prd",
       "---Architecture---",
       "architecture",
       "---New Section---",
       "new-section",
       "---Epics---",
       "epics",
       "---Guides---",
       "guides"
     ]
   }
   ```

## MDX Features

### Code Blocks
````mdx
```python title="example.py"
def extract_acm_records(pdf_path: str) -> list[ACMRecord]:
    """Extract ACM records from a PDF document."""
    ...
```
````

### Callouts
```mdx
<Callout type="info">
  Informational callout text.
</Callout>

<Callout type="warn">
  Warning callout text.
</Callout>
```

### Tables
Standard markdown tables are supported:
```mdx
| Column A | Column B |
|----------|----------|
| Value 1  | Value 2  |
```

## Theming

The docs layout uses VAEA branding via the Fumadocs theme system. Customization is in `src/app/docs/layout.tsx`:

- Sidebar background, link colors, and active states inherit from VAEA tokens
- The `RootProvider` from `fumadocs-ui/provider/next` provides framework integration
- `fumadocs-ui/style.css` is imported in the root layout for base styles

## Troubleshooting

### `.source` import errors
The `.source/` directory is auto-generated by `fumadocs-mdx` during build. If you see import errors:
```bash
rm -rf .source && npm run build
```

### TypeScript errors on `page.data.body`
The `src/lib/source.ts` file uses `toFumadocsSource()` to preserve type information. If you modify source.ts, ensure the `toFumadocsSource` import from `fumadocs-mdx/runtime/server` is intact.

### Sidebar not showing new pages
Check that:
1. The page has valid frontmatter with `title`
2. The section's `meta.json` includes the page filename (without `.mdx`)
3. The root `meta.json` includes the section directory name
