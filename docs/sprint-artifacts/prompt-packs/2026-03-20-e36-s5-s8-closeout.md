## E36-S7: Devil's Advocate Review (SP: 2)

**Goal:** Adversarial review of MCS8-MCS13 + jobs/source unification for edge cases,
false positives, flaky behavior, and data quality issues.

### Areas to Challenge

**MCS8 (Ghost save fix):**
- Does repo_create still silently fail in any edge case?
- What happens if SurrealDB is unreachable mid-save?

**MCS9 (SSE save events):**
- Does `ai.save_complete` always fire, even if only 0 records saved?
- Race condition: what if extraction fails between `save_started` and `save_complete`?

**MCS10 (Query invalidation timing):**
- If extraction completes in < 500ms, does the query invalidation still fire?
- Does `ai.building_extracted` fire for EVERY building or only successfully saved ones?

**MCS11 (Jobs/source unification):**
- What happens with a source that has 0 buildings?
- What if building selection is lost on page reload?
- Does BuildingTabStrip handle 20+ buildings without UI breakdown?

**MCS12 (extraction.* events):**
- Does `extraction.failed` fire on ALL error paths or only some?
- What if the SSE stream drops mid-extraction — does the UI show "stuck" state?

**MCS13 (internal_id collision fix):**
- Is the source_suffix suffix unique enough for sources with very long titles?
- Does internal_id stay stable across re-extractions of the same source?

### Output Format

For each area, document:
- **Risk found:** what could go wrong
- **Severity:** P0/P1/P2
- **Recommendation:** test to add, or code fix needed
