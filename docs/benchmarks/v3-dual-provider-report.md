## Overview

This report documents the accuracy of the V3 dual-provider extraction pipeline
(Docling + MinerU) against ground-truth benchmark documents. It validates the
acceptance criteria (AC1–AC6) from E31-S6.

Three extraction modes are benchmarked per document:

| Mode | Description |
|------|-------------|
| `docling_only` | Docling extractor only (`V3_DUAL_PROVIDER=false`) |
| `mineru_only` | MinerU extractor only (`V3_DUAL_PROVIDER=false`, `ACM_EXTRACTION_PROVIDER=mineru`) |
| `consensus` | Dual-provider with page-level consensus (`V3_DUAL_PROVIDER=true`, `MINERU_ENABLED=true`) |

## Notes

- MinerU fixtures were manually curated from known PDF table content using the
  Docling fixture as source of truth. Replace with live MinerU output when a
  GPU-equipped machine is available (see E31-S6 section 8, Option A).
- `benchmarks/fixtures/mineru_broadmeadows.json` and `mineru_alexander.json`
  use `table_type: "mineru_direct_api"` to distinguish them from Docling tables.
- High-stakes fields (`result`, `friable`, `material_condition`, `product`)
  were chosen because errors in these fields have compliance consequences.
- `material_condition` maps to the `condition` field name used in the
  story text; the schema field name in `ACMExtractionRecord` is
  `material_condition`.
