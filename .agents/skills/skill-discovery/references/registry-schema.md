# Skills Registry JSON Schema

## Overview

`skills-registry.json` is generated by `scan_registry.sh` at the repo root. It catalogs all AI capabilities available in the project: skills, commands, hooks, and rule categories.

## Top-Level Structure

```json
{
  "version": "1.0",
  "scanned_at": "2026-03-13T10:00:00Z",
  "skills": [...],
  "commands": [...],
  "hooks": [...],
  "rules": { ... }
}
```

| Field | Type | Description |
|-------|------|-------------|
| `version` | string | Schema version (currently `"1.0"`) |
| `scanned_at` | string | ISO-8601 UTC timestamp of when the scan ran |
| `skills` | array | All discovered skills, sorted by name |
| `commands` | array | Command files from `commands/` directory, sorted by name |
| `hooks` | array | Hook scripts from `.claude/hooks/`, sorted by name |
| `rules` | object | CLAUDE.md section headers as rule category index |

## `skills` Array — Skill Entry

```json
{
  "name": "planning-with-files",
  "description": "Persistent markdown-based planning system for session continuity.",
  "location": ".claude/skills/planning-with-files/SKILL.md",
  "also_at": [".agents/skills/planning-with-files/SKILL.md"],
  "has_scripts": true,
  "has_references": false,
  "platform": ["claude-code", "agents"]
}
```

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `name` | string | Yes | Skill name from YAML frontmatter `name:` field, or directory name as fallback |
| `description` | string | Yes | Description from YAML frontmatter `description:` field |
| `location` | string | Yes | Primary path to `SKILL.md`, relative to repo root |
| `also_at` | string[] | No | Additional paths where the same skill exists (cross-platform copies) |
| `has_scripts` | boolean | Yes | True if the skill directory contains a non-empty `scripts/` subdirectory |
| `has_references` | boolean | Yes | True if the skill directory contains a non-empty `references/` subdirectory |
| `platform` | string[] | Yes | Platforms where this skill is installed. Values: `"claude-code"` (`.claude/skills/`) and/or `"agents"` (`.agents/skills/`) |

### Platform Values

| Value | Source Directory | Usage Context |
|-------|-----------------|---------------|
| `"claude-code"` | `.claude/skills/` | Used by Claude Code (claude.ai/code) |
| `"agents"` | `.agents/skills/` | Used by the agents framework |

### Deduplication Rule

Skills with the same `name` that appear in both `.claude/skills/` and `.agents/skills/` are merged into a single entry. The first-seen location becomes `location`; the second becomes the first entry of `also_at`.

## `commands` Array — Command Entry

```json
{
  "name": "source_commands",
  "description": "Command handlers for document source processing",
  "location": "commands/source_commands.py"
}
```

| Field | Type | Description |
|-------|------|-------------|
| `name` | string | Command name derived from filename (without extension) |
| `description` | string | From frontmatter `description:` or first meaningful non-blank line after frontmatter; defaults to `"No description"` or `"Python command handler"` |
| `location` | string | Path relative to repo root |

### Command Sources

- `commands/*.md` — Markdown-based commands (slash commands, skill invocations)
- `commands/*.py` — Python surreal-commands worker handlers

---

## `hooks` Array — Hook Entry

```json
{
  "name": "pre-tool-use.sh",
  "trigger": "PreToolUse"
}
```

| Field | Type | Description |
|-------|------|-------------|
| `name` | string | Hook filename |
| `trigger` | string | Inferred trigger type based on filename convention (see table below) |

### Trigger Type Mapping

| Filename Pattern | Trigger Value |
|-----------------|---------------|
| `pre-tool-use*` | `PreToolUse` |
| `post-tool-use*` | `PostToolUse` |
| `pre-commit*` | `PreCommit` |
| `session-start*` | `SessionStart` |
| `ralph-gate-*` | `RalphGate` |
| `ralph-progress*` | `RalphProgress` |
| `ralph-stop*` | `RalphStop` |
| `scope-guard*` | `ScopeGuard` |
| `story-done*` | `StoryDone` |
| `task-quality*` | `TaskQualityGate` |
| `auto-commit*` | `PostCommit` |
| `stop*` | `Stop` |
| (anything else) | `Custom` |

## `rules` Object — Rule Categories

```json
{
  "source": "CLAUDE.md",
  "sections": [
    "CRITICAL PATH RULE (WSL/Windows)",
    "Project Overview",
    "Essential Commands",
    "Architecture",
    "Database",
    "Environment Variables",
    "Code Style"
  ]
}
```

| Field | Type | Description |
|-------|------|-------------|
| `source` | string | The file that was parsed (always `"CLAUDE.md"`) |
| `sections` | string[] | All `## ` level section headers, in document order |

## Usage Examples

### Find all skills with scripts

```python
import json
with open("skills-registry.json") as f:
    registry = json.load(f)

scripted = [s for s in registry["skills"] if s["has_scripts"]]
for s in scripted:
    print(s["name"], "->", s["location"])
```

### List skills available on both platforms

```python
both_platforms = [
    s for s in registry["skills"]
    if "claude-code" in s["platform"] and "agents" in s["platform"]
]
```

### Find debugging skills

```python
debug_skills = [
    s for s in registry["skills"]
    if "debug" in s["name"].lower() or "debug" in s["description"].lower()
]
```

### Count by category

```python
print(f"Skills:   {len(registry['skills'])}")
print(f"Commands: {len(registry['commands'])}")
print(f"Hooks:    {len(registry['hooks'])}")
print(f"Rules:    {len(registry['rules']['sections'])}")
```
